## API 변경 대응에 드는 반복 확인 업무

여러 쇼핑몰과 연동하는 OMS에서는 API 규격 변경을 놓치면 주문·배송 연동에 문제가 생길 수 있습니다. 당시 주요 쇼핑몰의 변경 검토에 **약 3시간**이 들었고, 메일·개발자센터·릴리즈노트에서 공지를 찾은 뒤 API 사용 여부와 코드 위치를 반복해서 검색했습니다.

## 근거를 남기는 4단계 자동화 파이프라인

반복 수집·대조를 줄이면서 개발자가 검토할 근거를 남기도록, Claude Cowork 스킬을 **공지 수집 → 변경 선별 → 코드 대조 → 리포트 생성**으로 구성했습니다. 공지 목록에서 끝내지 않고 상세 원문을 확인하며, 게시일과 실제 시행일을 구분했습니다.

쇼핑몰마다 공지 경로와 호출부 단서가 달라, 공통 검토 절차와 몰별 설정을 분리했습니다. 새 쇼핑몰은 수집 경로·코드 단서·예외를 설정 파일에 추가해 같은 절차로 검토하도록 했습니다.

## 코드 대조에서 발견한 오탐과 검증 규칙 보완

이 파이프라인의 코드 대조 단계에서 미사용 API 선언이나 테스트·보관용 파일도 검색됐습니다. 이름이 있다는 이유만으로 사용 중이라고 판단하면, 실제로 호출하지 않는 코드까지 대응 대상으로 잡는 오탐이 생길 수 있었습니다.

**API 선언 → 활성 호출 매핑 → 응답 파싱 여부**를 단계별로 확인하도록 규칙을 보완했습니다. 응답 필드가 제거되는 변경은 그 필드를 실제로 읽는지도 확인하고, 테스트·보관용 코드는 영향 판단의 근거에서 제외했습니다. 근거가 부족한 항목은 추측하지 않고 공지 출처·코드 위치와 함께 **확인 불가**로 표시했습니다.

## 검토 시간 단축과 개발자의 최종 판단 유지

주요 쇼핑몰 API 변경 검토는 **약 3시간에서 15분으로 줄었습니다.** 개발자는 리포트의 원문·코드 위치·확인 불가 항목을 확인해 대응 여부를 판단하고 실제 코드를 수정합니다.

담당자의 확인 절차를 명시적인 규칙과 근거로 남기고, 불확실한 판단과 실제 변경은 사람이 맡도록 자동화 범위를 정했습니다.
