## 쇼핑몰별 변경 공지 수집과 코드 대조 자동화

여러 쇼핑몰과 연동하는 OMS에서는 API 요청·응답 규격이 바뀌면 우리 코드도 수정해야 하는지 확인해야 했습니다. 기존에는 메일·개발자센터·릴리즈노트를 직접 찾아보고, 사용 중인 API와 코드 위치를 다시 검색했습니다.

반복되는 수집·대조를 줄이되 대응 판단의 근거는 남기도록, Claude Cowork 스킬을 **공지 수집 → 변경 선별 → 코드 대조 → 리포트 생성**으로 나눴습니다. 상세 원문의 게시일·시행일을 구분하고 최종 대응은 개발자가 판단하게 했습니다.

쇼핑몰마다 공지 경로와 코드 검색 단서가 달라, 새 쇼핑몰을 추가할 때 공통 절차까지 고치지 않도록 몰별 설정을 분리했습니다.

## 검색된 API 선언과 실제 사용 코드를 구분

자동화 초기에는 미사용 API 선언이나 테스트·보관용 파일도 검색됐습니다. 검색 결과에 이름이 있다는 이유만으로 영향이 있다고 판정하면, 실제로 호출하지 않는 코드까지 대응 대상으로 잡을 수 있었습니다.

**API 선언 → 활성 호출 매핑 → 응답 파싱**을 확인하도록 규칙을 보완했습니다. 응답 필드가 제거되는 변경은 해당 필드를 실제로 읽는지도 확인했습니다. 근거가 부족하면 추측하지 않고 공지 출처·코드 위치와 함께 확인 불가로 남겼습니다.
