## 공지를 찾는 일과 영향을 판단하는 일 분리하기

쇼핑몰마다 메일·개발자센터·릴리즈노트로 공지를 전달했고, 공지를 찾은 뒤에도 실제 연동 코드와 대조해야 했습니다. 사람이 반복해서 소비하는 시간을 줄이되 판단 근거를 잃지 않는 범위가 필요했습니다.

Claude Cowork 스킬을 공지 수집, 변경 선별, 코드 대조, 리포트 생성으로 나눴습니다. 목록에서 여러 공지가 섞이는 문제를 피하도록 상세 원문을 확인하고, 게시일과 시행일도 따로 보게 했습니다. 주요 쇼핑몰 검토는 약 3시간에서 15분으로 줄었고, 대응 판단과 코드 수정은 담당 개발자가 수행하도록 했습니다.

## 검색된 코드가 실제 사용 코드인지 확인하기

초기에는 사용하지 않는 상수나 보관용 파일도 검색 결과에 포함됐습니다. 최신 모듈이라는 이유로 실제 호출 위치를 잘못 잡기도 했고, API를 호출하더라도 종료되는 응답 필드를 사용하지 않는 경우가 있었습니다.

상수 선언에서 끝내지 않고 활성 호출 매핑과 응답 파싱까지 확인하도록 규칙을 보완했습니다. 테스트·보관용 코드는 근거에서 제외하고, 확정하기 어려운 항목은 확인 불가로 남겼습니다. 리포트에는 공지 출처와 확인할 코드 위치를 함께 넣었습니다.

## 쇼핑몰 추가 시 공통 절차까지 바뀌지 않게 하기

쇼핑몰마다 수집 경로와 호출부 단서, 예외가 달랐습니다. 이를 모두 스킬 본문에 넣으면 쇼핑몰 하나를 추가할 때 전체 검토 절차를 건드려야 했습니다.

공통 판단 기준과 리포트 형식은 스킬에 두고, 쇼핑몰별 경로·코드 단서·예외는 설정 파일로 분리했습니다. 새 쇼핑몰은 설정 파일을 추가해 같은 검토 흐름에 연결하도록 구성했습니다.
