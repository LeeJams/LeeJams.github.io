## 어떤 기능에서 어떤 문제가 있었는지

먼저 대상 화면·기능의 용도를 설명합니다. 이어 실제로 관찰한 현상과 조건을 적습니다. '뒤 페이지', '이전 값', '원본' 같은 표현은 무엇을 가리키는지 앞에서 밝혀야 합니다.

어떤 코드·실행 계획·재현 결과를 확인해 원인을 판단했는지 적고, 그 근거에서 해결 방식으로 이어갑니다. 상단에 수치가 있어도 원인을 이해하는 데 필요한 현상과 조건은 본문에서 생략하지 않습니다. 확인하지 않은 분석 과정은 만들지 않습니다.

## 해결하면서 지켜야 했던 조건

이 조건이 앞의 변경과 어떻게 연결되는지 설명하고, 선택한 방식과 검증 결과를 적습니다. 다른 기능의 이야기라면 그 기능의 맥락부터 다시 소개합니다.

실제 장애와 설계 단계에서 예방한 위험을 구분합니다. 예방 설계는 먼저 요구 조건을 적고 선택 이유로 연결합니다. 짧게 쓰되 논리의 연결을 없애지 않으며, 기능 나열·자기소개·반복되는 결론은 생략합니다.
